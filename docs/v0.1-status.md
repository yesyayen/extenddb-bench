## Known issues / v0.2 line items added during v0.1

These come up through implementation; they are now `v0.2` items, not v0.1 scope creep.

- **LG saturation safety belt**: a hard cap on in-flight tokio tasks (8 ×
  `--connections`) prevents the LG from OOMing or losing SSM connectivity when
  the SUT can't keep up. Overflow drops are counted in `errors_total`.
  Followup: separate `lg_overflow_total` counter so the saturation rule can
  distinguish "SUT failed" from "LG dropped".
- **Achieved RPS overshoot**: governor's default per-second quota allows a
  full second's worth of burst, so achieved_rps can briefly exceed target_rps
  in low-RPS steps. Followup: switch to `Quota::with_period` for tighter
  pacing.
- **bind_addr workaround**: ExtendDB's `init` sets the cert SANs from
  `--bind-addr` but does not write the same value into the rendered
  `bind_addr` config field — the user-data writes it explicitly with `sed`.
- **TLS-insecure mode**: the bench currently runs with `--tls-insecure`
  by default. The OS-trust-store path (LG installs SUT cert via
  `update-ca-trust extract`) should also work but was not the path that the
  first acceptance run used.
- **Volume reattach during stack update**: changing user-data triggers
  instance replacement, but `CfnVolumeAttachment` doesn't orchestrate
  detach/reattach cleanly. v0.1 workaround: `cdk destroy && cdk deploy`.

## What remains for full v0.1 acceptance

1. Run the design's full default sweep (`1k,5k,25k,100k,250k`, 10/60/5s
   timings, 3 iterations) end-to-end with the inflight cap in place, and
   confirm summary.md.
2. Run that same sweep three times against the same SHA. Confirm relative
   stddev of `max_sustained_rps` across the three runs is < 5%.
3. (optional) Verify SSM port-forward to LG :9090 reaches the live
   Prometheus exposition during a run.

After those three, v0.1 is fully accepted per the design doc.
